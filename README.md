# Навчальна платформа (тимчасова назва)

Назву, слоган і опис для сайту змінюйте в одному місці: `frontend/brand.config.json`.

Вебплатформа для вчителів: тести (4 типи завдань, зображення в питаннях,
таймер, розбір відповідей), картки для запам'ятовування, кабінет учня та панель вчителя.

**Стек:** Java 17, Spring Boot 3.2.5 (Web, Data JPA, Security), PostgreSQL 16, Flyway, JWT (JJWT 0.12.5),
React 19, Vite, Tailwind CSS 4, Axios.

## Можливості

**Учень:** реєстрація (логін, ім'я, прізвище, пароль; пошта не потрібна), тести з таймером, результат за шкалою НМТ 100-200, розбір відповідей із поясненнями,
історія спроб і статистика (`/results`), картки з 3D-перевертанням і фото (завантаження з пристрою, стискається до 1000 px), зміна пароля (`/account`).

**Вчитель** (`/teacher`): створення, редагування й видалення тестів, питань (4 типи, зображення, пояснення, ліміт часу
на тест) і модулів карток; список учнів з результатами та розбором кожної спроби; скидання пароля й видалення учня.

Реєстрація через сайт створює лише учнів. Акаунт вчителя створюється автоматично при першому запуску на порожній БД.

## Розгортання (Docker Compose + автоматичний HTTPS)

Покрокова інструкція для початківців: [docs/deploy.md](docs/deploy.md).

Потрібні: сервер із Docker, домен, DNS A-запис на сервер, відкриті порти 80 і 443.

```bash
cp .env.example .env
# заповніть .env: DOMAIN, PUBLIC_URL (https://<DOMAIN>), POSTGRES_PASSWORD, JWT_SECRET (openssl rand -base64 48), BOOTSTRAP_TEACHER_PASSWORD
docker compose up -d --build
```

Сайт буде доступний на `https://<DOMAIN>`. Вхід початкового вчителя (лише якщо `BOOTSTRAP_TEACHER_ENABLED=true`): логін `teacher`, пароль із `BOOTSTRAP_TEACHER_PASSWORD`
(змінити в «Профілі» після першого входу). Застосунок у production-профілі **не стартує**, якщо не задано секрети.

Важливо: початковий вчитель створюється лише якщо його ще немає. Для нового клієнта використовуйте порожню БД
(у compose це новий том `pgdata`), не переносіть dev-базу.

> Файли розгортання (`Dockerfile`, `docker-compose.yml`, `frontend/nginx.conf`, `deploy/Caddyfile`) підготовлено,
> але на сервері з Docker ще не запускалися. Перший запуск варто зробити разом із клієнтом.

### Резервні копії

```bash
./scripts/backup.sh        # дамп у ./backups, зберігає копії за 30 днів
# приклад cron (щодня о 03:00): 0 3 * * * cd /opt/nmt-history && ./scripts/backup.sh
# відновлення:
gunzip -c backups/<файл>.sql.gz | docker compose exec -T db psql -U nmt nmt_history_db
```

Резервні копії варто копіювати за межі сервера.

### Оновлення

```bash
git pull && docker compose up -d --build
```

Схема БД оновлюється міграціями Flyway (`src/main/resources/db/migration`) автоматично при старті.

> **Перше оновлення до моделі власності матеріалів (етап 2)** вимагає резервної копії та явних змінних
> `LEGACY_TEACHER_USERNAME`, `ADMIN_USERNAME`, `ADMIN_PASSWORD`. Без них production-профіль не стартує. Покроково: [docs/stage2-migration.md](docs/stage2-migration.md).

## Локальна розробка

Потрібні JDK 17+, Node 22+ і PostgreSQL (найпростіше через Docker Desktop).

**1. База даних** (порт 5432, логін і пароль `postgres`):

```bash
docker compose -f docker-compose.dev.yml up -d
```

Без Docker встановіть PostgreSQL і створіть базу `nmt_history_db`.

**2. Бекенд** (API на :8080), у корені проєкту. Локальні акаунти (адмін, демо-вчитель, демо-учень) створюються з `config/application.yml` (див. нижче):

```bash
./mvnw spring-boot:run          # macOS, Linux, WSL, Git Bash
mvnw.cmd spring-boot:run        # Windows PowerShell / cmd
```

Якщо пароль PostgreSQL інший, задайте `DB_USERNAME` і `DB_PASSWORD` (PowerShell: `$env:DB_PASSWORD="..."`).

**Локальні акаунти.** Файл `config/application.yml` (у `.gitignore`, у репозиторій не потрапляє) підхоплюється автоматично, якщо бекенд запускати з кореня проєкту:

```yaml
app:
  admin:            # ADMIN, створюється AdminBootstrap
    username: admin123
    password: <ваш пароль, від 12 символів>
  demo:             # необов'язково: teacher_demo та student_demo (ігноруються в профілі prod)
    teacher-password: <пароль від 8 символів>
    student-password: <пароль від 8 символів>
```

Акаунти створюються при старті й не дублюються. Вчителі також реєструються самі (`/register/teacher`), але створювати матеріали можуть лише з активною підпискою, яку вручну активує адміністратор (розділ «Користувачі»); учні реєструються за особистим кодом вчителя.

**3. Фронтенд** (http://localhost:45173), в іншому терміналі:

```bash
cd frontend
npm install
npm run dev
```

Бекенд і фронтенд мають працювати одночасно, а база має бути запущена до бекенду.

Тести бекенду: `./mvnw test` (юніт- та інтеграційні тести на H2). Фронтенд: `npm run lint && npm run build`.

Змінні середовища (для dev усі мають значення за замовчуванням): `DB_URL`, `DB_USERNAME`, `DB_PASSWORD`,
`SERVER_PORT`, `JWT_SECRET`, `JWT_EXPIRATION_MS`, `CORS_ALLOWED_ORIGINS`, `BOOTSTRAP_TEACHER_*`,
`LOGIN_MAX_FAILURES`, `LOGIN_WINDOW_MINUTES`. Для фронтенду `VITE_API_URL` (dev: `http://localhost:8080/api`,
production-збірка: `/api`).

## Правила оцінювання

SINGLE_CHOICE: 1 бал. MULTIPLE_CHOICE: +1 за правильний вибір, -1 за зайвий (мінімум 0). MATCHING: 1 бал за пару.
CHRONOLOGY: 1 бал за повністю правильний ряд. Первинний бал переводиться в шкалу 100-200 **лінійно**
(`NmtScoreConverter`); це орієнтовна оцінка, а не офіційна таблиця переведення НМТ.

Формат даних питання: у MATCHING кожен варіант є елементом лівої колонки, а `matchKey` це його правильний відповідник;
у CHRONOLOGY `orderIndex` задає правильну позицію події.

## Робота над помилками та статистика

- Учень: у шапці «Помилки» (`/practice`). Збирає питання, на які учень востаннє відповів неправильно (до 20 за раз).
  Правильна відповідь прибирає питання зі списку, помилка залишає його. Ці повторення не впливають на бали й історію результатів.
- Вчитель: у редакторі тесту блок «Статистика по питаннях»: частка помилок по кожному питанню, найскладніші зверху.
- Теми: у формі питання є необов'язкове поле «Тема». За ним учень бачить «Успішність по темах» на сторінці «Мої результати», а вчитель, вибравши учня, бачить його слабкі теми.

## Реєстрація учнів

Реєстрація вимагає код запрошення. Він створюється автоматично; вчитель бачить його у вкладці «Учні та результати»,
може скопіювати, згенерувати новий або задати власний через API (`PUT /api/teacher/invite-code`). Після зміни коду старий перестає працювати.
Код не захищає від учня, який сам передав його стороннім, тому за потреби просто змініть його.

## Контроль під час тесту

- Час відліку починається на сервері (`POST /api/tests/{id}/start`) і не скидається перезавантаженням сторінки.
  Відповідь, надіслана пізніше ніж через 30 с після завершення часу, зберігається з позначкою «прострочено»; вчитель бачить її в таблиці результатів.
- Під час тесту заблоковані переходи по посиланнях і кнопка «Назад», при закритті вкладки браузер просить підтвердження.
- Згортання вкладки, перехід в інше вікно чи на інший сайт фіксуються (кількість зберігається на сервері й видна вчителю).
  Якщо учень відсутній понад 15 с (`AWAY_LIMIT_SECONDS` у `TestSession.jsx`), тест завершується автоматично з позначкою «покинув сторінку».
- Це стримувальний захід, а не захист від списування: браузер не може гарантувати нічого (другий пристрій, телефон поруч).
  Крім того, відкриття панелі розробника чи системного діалогу теж може зарахуватися як вихід зі сторінки.
- Відповіді зберігаються лише в браузері до завершення: при перезавантаженні сторінки введені відповіді втрачаються, а час продовжує йти.

## Обмеження

- Відновлення пароля через пошту не реалізовано: вчитель задає учневі новий пароль, учень змінює його в «Профілі».
- Шкала НМТ лінійна (див. вище), в інтерфейсі вона позначена як «орієнтовна». Офіційна таблиця переведення щороку інша й у проєкт не внесена.
  Базу питань потрібно наповнити вчителю.
- Блокування входу після невдалих спроб зберігається в БД (таблиця `login_failures`) і переживає перезапуск.
